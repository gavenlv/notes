# 第4章：查询语言和数据处理

## 4.1 查询语言概述

Grafana本身不存储数据，而是通过查询语言从各种数据源获取数据。不同的数据源使用不同的查询语言，掌握这些语言是有效使用Grafana的关键。

### 4.1.1 主要查询语言

- **PromQL**: Prometheus的查询语言，用于时序数据
- **Flux**: InfluxDB 2.0的查询语言，功能强大
- **InfluxQL**: InfluxDB 1.x的类SQL查询语言
- **SQL**: 关系数据库的标准查询语言
- **LogQL**: Loki的日志查询语言

### 4.1.2 查询语言选择原则

1. **数据源决定语言**: 不同数据源使用不同查询语言
2. **性能考虑**: 某些语言在特定场景下性能更优
3. **功能需求**: 复杂分析需要更强大的查询语言
4. **团队技能**: 选择团队熟悉的语言

## 4.2 PromQL深入解析

### 4.2.1 PromQL基础语法

PromQL是Prometheus的查询语言，专门为时序数据设计。

#### 数据类型

- **瞬时向量(Instant vector)**: 单个时间点的数据点集合
- **范围向量(Range vector)**: 一段时间内的数据点集合
- **标量(Scalar)**: 简单的数字值
- **字符串(String)**: 文本值

#### 基础查询示例

```promql
# 瞬时向量查询 - 获取当前值
up
node_cpu_seconds_total

# 范围向量查询 - 获取一段时间内的数据
node_cpu_seconds_total[5m]
up[1h]

# 带标签过滤
node_cpu_seconds_total{mode="idle", instance="server01"}
up{job="prometheus"}

# 正则表达式匹配
up{instance=~"server.*"}
up{instance!~"test.*"}
```

### 4.2.2 聚合操作

聚合操作是PromQL的核心功能，用于对多个时间序列进行汇总。

#### 基础聚合函数

```promql
# 求和
sum(up)
sum by (job) (up)

# 平均值
avg(node_cpu_seconds_total)
avg by (instance, mode) (node_cpu_seconds_total)

# 最大值/最小值
max(node_memory_MemTotal_bytes)
min by (instance) (node_memory_MemTotal_bytes)

# 计数
count(up)
count by (job) (up)

# 分位数
quantile(0.95, http_request_duration_seconds)
```

#### 分组聚合

```promql
# 按实例分组计算CPU使用率
avg by (instance) (irate(node_cpu_seconds_total[5m])) * 100

# 按作业和实例分组
sum by (job, instance) (http_requests_total)

# 排除某些标签
sum without (mode) (node_cpu_seconds_total)
```

### 4.2.3 数学运算

PromQL支持丰富的数学运算。

#### 算术运算

```promql
# 基本运算
node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes

# 百分比计算
(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / node_memory_MemTotal_bytes * 100

# 使用标量
node_filesystem_size_bytes / 1024 / 1024 / 1024  # 转换为GB

# 布尔运算
up == 1
node_load1 > 2
```

#### 函数运算

```promql
# 变化率计算
rate(http_requests_total[5m])
irate(http_requests_total[5m])

# 增量计算
increase(http_requests_total[1h])

# 绝对值
abs(node_network_receive_bytes_total)

# 对数运算
log2(node_memory_MemTotal_bytes)

# 时间函数
time() - process_start_time_seconds
```

### 4.2.4 高级查询技巧

#### 子查询

```promql
# 计算5分钟内的平均QPS
avg_over_time(
  rate(http_requests_total[5m])[1h:5m]
)

# 计算每小时的最大内存使用率
max_over_time(
  (node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes)[1h:1m]
) / node_memory_MemTotal_bytes * 100
```

#### 预测和趋势分析

```promql
# 线性预测
predict_linear(node_filesystem_free_bytes[1h], 3600)

# 直方图分位数
histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m]))

# 变化检测
delta(node_network_receive_bytes_total[5m])
```

## 4.3 Flux查询语言

### 4.3.1 Flux基础概念

Flux是InfluxDB 2.0的查询语言，功能强大且表达力强。

#### 管道操作

Flux使用管道操作符`|>`连接多个操作。

```flux
// 基础查询管道
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")
  |> filter(fn: (r) => r._field == "usage")
  |> aggregateWindow(every: 1m, fn: mean)
```

#### 数据类型和结构

```flux
// 表结构示例
// _measurement: cpu
// _field: usage
// _time: 2023-01-01T00:00:00Z
// _value: 0.75
// host: server01
// region: us-west
```

### 4.3.2 常用操作函数

#### 过滤和选择

```flux
// 基础过滤
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")
  |> filter(fn: (r) => r._field == "usage")
  |> filter(fn: (r) => r.host == "server01")

// 多条件过滤
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => 
    r._measurement == "cpu" and 
    (r.host == "server01" or r.host == "server02")
  )
```

#### 聚合和转换

```flux
// 时间窗口聚合
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")
  |> aggregateWindow(
    every: 1m,
    fn: mean,
    createEmpty: false
  )

// 分组聚合
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")
  |> group(columns: ["host"])
  |> mean()

// 数据转换
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "memory")
  |> map(fn: (r) => ({
    _time: r._time,
    _value: r._value / 1024 / 1024,  // 转换为MB
    _field: "memory_mb"
  }))
```

### 4.3.3 高级Flux功能

#### 连接和联合

```flux
// 数据连接
cpu_data = from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "cpu")

memory_data = from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "memory")

union(tables: [cpu_data, memory_data])
  |> sort(columns: ["_time"])
```\n
#### 自定义函数

```flux
// 定义自定义函数
usagePercentage = (used, total) => (used / total) * 100.0

// 使用自定义函数
from(bucket: "mybucket")
  |> range(start: -1h)
  |> filter(fn: (r) => r._measurement == "memory")
  |> map(fn: (r) => ({
    _time: r._time,
    _value: usagePercentage(
      r._field == "used" ? r._value : 0,
      r._field == "total" ? r._value : 1
    ),
    _field: "usage_percent"
  }))
```

## 4.4 SQL查询技巧

### 4.4.1 基础SQL查询

当使用MySQL、PostgreSQL等关系数据库作为数据源时，需要使用SQL查询。

#### 时间序列查询

```sql
-- 基础时间序列查询
SELECT 
    timestamp,
    metric_value 
FROM metrics 
WHERE metric_name = 'cpu_usage' 
    AND timestamp >= NOW() - INTERVAL 1 HOUR
ORDER BY timestamp ASC

-- 带标签过滤
SELECT 
    timestamp,
    metric_value,
    JSON_EXTRACT(tags, '$.host') as host
FROM metrics 
WHERE metric_name = 'cpu_usage' 
    AND JSON_EXTRACT(tags, '$.host') = 'server01'
    AND timestamp >= NOW() - INTERVAL 1 HOUR
ORDER BY timestamp ASC
```

### 4.4.2 聚合和分组

```sql
-- 时间窗口聚合
SELECT 
    DATE_FORMAT(timestamp, '%Y-%m-%d %H:%i:00') as time_bucket,
    AVG(metric_value) as avg_usage
FROM metrics 
WHERE metric_name = 'cpu_usage'
    AND timestamp >= NOW() - INTERVAL 1 HOUR
GROUP BY time_bucket
ORDER BY time_bucket ASC

-- 多维度分组
SELECT 
    DATE(timestamp) as date,
    JSON_EXTRACT(tags, '$.host') as host,
    AVG(metric_value) as avg_usage,
    MAX(metric_value) as max_usage
FROM metrics 
WHERE metric_name = 'cpu_usage'
    AND timestamp >= NOW() - INTERVAL 7 DAY
GROUP BY date, host
ORDER BY date DESC, host ASC
```

### 4.4.3 高级SQL技巧

#### 窗口函数

```sql
-- 使用窗口函数计算移动平均
SELECT 
    timestamp,
    metric_value,
    AVG(metric_value) OVER (
        ORDER BY timestamp 
        ROWS BETWEEN 5 PRECEDING AND CURRENT ROW
    ) as moving_avg
FROM metrics 
WHERE metric_name = 'cpu_usage'
    AND timestamp >= NOW() - INTERVAL 1 HOUR
ORDER BY timestamp ASC

-- 排名和分位数
SELECT 
    timestamp,
    metric_value,
    PERCENT_RANK() OVER (ORDER BY metric_value) as percentile
FROM metrics 
WHERE metric_name = 'response_time'
    AND timestamp >= NOW() - INTERVAL 1 HOUR
ORDER BY metric_value DESC
```

## 4.5 数据处理和转换

### 4.5.1 Grafana内置转换

Grafana提供了强大的数据转换功能，可以在查询后对数据进行处理。

#### 常用转换类型

```yaml
# 组织字段
Transformation: Organize fields
Config:
  excludeByName:
    Time: true
  indexByName:
    instance: 0
    Value: 1
  renameByName:
    Value: "CPU Usage (%)"

# 过滤数据
Transformation: Filter data by values
Config:
  filters:
    - fieldName: Value
      config:
        type: range
        min: 0
        max: 100

# 合并时间序列
Transformation: Merge series
Config:
  byField: instance
```

#### 计算字段

```yaml
Transformation: Add field from calculation
Config:
  mode: binary operation
  binary:
    left: Value
    operator: *
    right: 100
  alias: "Percentage"
```

### 4.5.2 自定义转换

#### JavaScript转换

```javascript
// 自定义JavaScript转换
return data.map(frame => {
  return {
    ...frame,
    fields: frame.fields.map(field => {
      if (field.name === 'value') {
        return {
          ...field,
          values: field.values.map(v => v * 100),
          config: {
            ...field.config,
            unit: 'percent'
          }
        };
      }
      return field;
    })
  };
});
```

## 4.6 查询优化技巧

### 4.6.1 性能优化原则

1. **减少数据量**: 使用合适的时间范围和聚合
2. **优化查询语法**: 避免复杂的正则表达式
3. **利用索引**: 确保查询字段有索引
4. **缓存策略**: 合理设置查询缓存

### 4.6.2 具体优化技巧

#### PromQL优化

```promql
# 不好的查询 - 范围过大
rate(http_requests_total[1h])

# 优化后的查询 - 合适的时间范围
rate(http_requests_total[5m])

# 不好的查询 - 复杂正则
up{instance=~"server[0-9]{1,3}"}

# 优化后的查询 - 精确匹配
up{instance=~"server1|server2|server3"}
```

#### SQL优化

```sql
-- 不好的查询 - 全表扫描
SELECT * FROM metrics WHERE metric_value > 0.5

-- 优化后的查询 - 使用索引
SELECT * FROM metrics 
WHERE metric_name = 'cpu_usage' 
    AND metric_value > 0.5
    AND timestamp >= NOW() - INTERVAL 1 HOUR

-- 创建合适的索引
CREATE INDEX idx_metrics_name_time ON metrics(metric_name, timestamp);
CREATE INDEX idx_metrics_value ON metrics(metric_value);
```

### 4.6.3 监控查询性能

#### 使用Explain分析
