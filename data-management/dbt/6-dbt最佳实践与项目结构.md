# 第6章：dbt最佳实践与项目结构

## 概述
本章深入探讨dbt项目的最佳实践和标准项目结构，帮助您构建可维护、可扩展的数据转换项目。

## 6.1 项目结构设计原则

### 6.1.1 模块化设计
- **分层架构**: staging → intermediate → marts
- **职责分离**: 每个模型专注于单一职责
- **可复用性**: 通过宏和包实现代码复用

### 6.1.2 可维护性考虑
- **命名规范**: 统一的文件命名约定
- **文档化**: 完整的模型和字段文档
- **测试覆盖**: 全面的数据质量测试

### 6.1.3 可扩展性设计
- **插件架构**: 支持自定义宏和操作
- **配置管理**: 环境特定的配置管理
- **依赖管理**: 清晰的依赖关系管理

## 6.2 标准项目结构

### 6.2.1 核心目录结构
```
project_name/
├── dbt_project.yml          # 项目配置文件
├── profiles.yml             # 数据库连接配置
├── models/                  # 数据模型目录
│   ├── staging/            # 数据清洗层
│   ├── intermediate/       # 中间层
│   ├── marts/              # 业务集市层
│   └── utils/              # 工具模型
├── macros/                 # 自定义宏
│   ├── date_utils.sql      # 日期工具宏
│   ├── data_quality.sql    # 数据质量宏
│   └── business_logic.sql  # 业务逻辑宏
├── tests/                  # 测试文件
│   ├── sources/            # 数据源测试
│   ├── models/             # 模型测试
│   └── macros/             # 宏测试
├── seeds/                  # 种子数据
├── snapshots/             # 快照配置
├── analyses/              # 分析查询
├── target/                # 编译输出
├── logs/                  # 日志文件
└── docs/                  # 文档文件
```

### 6.2.2 模型分层详解

#### staging层 (数据清洗层)
- **目的**: 数据标准化和基础清洗
- **特点**: 接近源表结构，轻量转换
- **命名**: stg_前缀

#### intermediate层 (中间层)
- **目的**: 业务逻辑实现和指标计算
- **特点**: 跨表关联，复杂计算
- **命名**: int_前缀

#### marts层 (业务集市层)
- **目的**: 面向业务用户的最终表
- **特点**: 业务友好，聚合数据
- **命名**: dim_/fct_前缀

## 6.3 命名规范最佳实践

### 6.3.1 文件命名规范
- **模型文件**: 使用蛇形命名法 (snake_case)
- **宏文件**: 描述性名称，功能明确
- **测试文件**: 与被测对象对应

### 6.3.2 模型命名规范
- **staging层**: `stg_源系统_表名`
- **intermediate层**: `int_业务域_功能`
- **marts层**: `dim_维度名` / `fct_事实名`

### 6.3.3 字段命名规范
- **业务字段**: 使用业务术语
- **技术字段**: 明确技术含义
- **标识字段**: 统一命名规则

## 6.4 配置管理最佳实践

### 6.4.1 dbt_project.yml配置
```yaml
# 项目基础信息
name: "my_dbt_project"
version: "1.0.0"
profile: "my_profile"

# 模型配置
models:
  my_dbt_project:
    # staging层配置
    staging:
      +materialized: view
      +tags: ["staging"]
      
    # intermediate层配置  
    intermediate:
      +materialized: table
      +tags: ["intermediate"]
      
    # marts层配置
    marts:
      +materialized: table
      +tags: ["marts"]
```
