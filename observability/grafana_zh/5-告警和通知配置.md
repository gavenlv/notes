# 第5章：告警和通知配置

## 5.1 告警系统概述

Grafana的告警系统允许您基于监控数据自动检测问题并发送通知。告警是监控系统的核心功能，能够帮助您在问题影响用户之前及时发现并处理。

### 5.1.1 告警工作流程

```
数据源 → 告警规则 → 告警状态 → 通知渠道 → 接收者
   ↓         ↓         ↓         ↓         ↓
Prometheus  条件判断  Pending → Firing → Email/Slack → 运维团队
InfluxDB    阈值检测  正常状态  告警状态   Webhook    开发团队
MySQL       异常检测           恢复状态   PagerDuty   管理人员
```

### 5.1.2 告警核心概念

- **告警规则(Alert Rule)**: 定义何时触发告警的条件
- **告警状态(Alert State)**: 正常、Pending、Firing、恢复等状态
- **通知策略(Notification Policy)**: 定义告警如何发送给接收者
- **静默(Silence)**: 临时禁用特定告警
- **联系人(Contact Point)**: 告警通知的接收端点

## 5.2 告警规则配置

### 5.2.1 创建第一个告警规则

#### 通过UI创建告警

1. **进入告警管理**: 左侧菜单 → Alerting → Alert rules
2. **创建告警规则**: 点击"New alert rule"
3. **配置规则详情**:

```yaml
# 规则基本信息
Rule name: High CPU Usage
Folder: General
Group: System Alerts

# 查询配置
Data source: Prometheus
Query: 
  100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 条件配置
Condition: when avg() of query(A) is above 80
Evaluate every: 1m
For: 5m

# 标签和注释
Labels:
  severity: warning
  team: infrastructure

Annotations:
  summary: High CPU usage on {{ $labels.instance }}
  description: CPU usage is at {{ $value }}% on {{ $labels.instance }}
```

#### 通过API创建告警

```bash
# 创建告警规则API调用
curl -X POST http://localhost:3000/api/ruler/grafana/api/v1/rules/General \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '
{
  "name": "High CPU Usage",
  "interval": "1m",
  "rules": [
    {
      "expr": "100 - (avg by (instance) (irate(node_cpu_seconds_total{mode=\"idle\"}[5m])) * 100) > 80",
      "for": "5m",
      "labels": {
        "severity": "warning",
        "team": "infrastructure"
      },
      "annotations": {
        "summary": "High CPU usage on {{ $labels.instance }}",
        "description": "CPU usage is at {{ $value }}% on {{ $labels.instance }}"
      }
    }
  ]
}'
```

### 5.2.2 告警条件类型

Grafana支持多种告警条件判断方式：

#### 阈值告警

```yaml
# 简单阈值
Condition: when avg() of query(A) is above 80

# 范围阈值
Condition: when avg() of query(A) is outside range 20 to 80

# 多级阈值
Conditions:
  - when avg() of query(A) is above 80
    severity: warning
  - when avg() of query(A) is above 90
    severity: critical
```

#### 变化率告警

```yaml
# 突然增长告警
Condition: when diff() of query(A) is above 50

# 持续下降告警
Condition: when diff() of query(A) is below -30
```

#### 异常检测告警

```yaml
# 基于标准差的异常检测
Condition: when avg() of query(A) is above 2 * stddev() of query(A)

# 同比异常
Condition: when avg() of query(A) is above 1.5 * avg() of query(B)
```

### 5.2.3 高级告警规则

#### 复合条件告警

```yaml
# CPU和内存同时告警
Rule: System Resource Critical
Queries:
  A: 100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
  B: (node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / node_memory_MemTotal_bytes * 100

Condition: when avg() of query(A) is above 90 and avg() of query(B) is above 90
```

#### 依赖关系告警

```yaml
# 只有在上游服务正常时才检查下游服务
Rule: Downstream Service Health
Queries:
  A: up{job="upstream-service"}  # 上游服务状态
  B: up{job="downstream-service"}  # 下游服务状态

Condition: when avg() of query(A) == 1 and avg() of query(B) == 0
```

## 5.3 通知渠道配置

### 5.3.1 邮件通知配置

#### SMTP服务器配置

编辑`grafana.ini`配置文件：

```ini
[smtp]
enabled = true
host = smtp.gmail.com:587
user = your-email@gmail.com
password = your-app-password
from_address = your-email@gmail.com
from_name = Grafana Alerts

# TLS配置
skip_verify = false
cert_file =
key_file =
```

#### 创建邮件联系人

1. **进入联系人管理**: Alerting → Contact points
2. **创建联系人**: 点击"New contact point"
3. **选择类型**: Email
4. **配置参数**:

```yaml
Name: Email Alerts
Type: Email
Addresses:
  - admin@company.com
  - ops@company.com

# 邮件模板
Subject: [{{ .Status | toUpper }}] {{ .GroupLabels.alertname }}
Message: |
  {{ range .Alerts }}
  *Alert:* {{ .Annotations.summary }}
  *Description:* {{ .Annotations.description }}
  *Instance:* {{ .Labels.instance }}
  *Time:* {{ .StartsAt.Format "2006-01-02 15:04:05" }}
  {{ end }}
```

#### 创建Slack应用

1. 访问 https://api.slack.com/apps
2. 创建新的Slack应用
3. 启用Incoming Webhooks
4. 获取Webhook URL

#### 配置Slack联系人


### 5.3.3 Webhook通知配置

#### 自定义Webhook集成

```yaml
Name: Custom Webhook
Type: Webhook
URL: https://your-api.com/alerts

# HTTP配置
HTTP Method: POST
HTTP Headers:
  Authorization: Bearer your-token
  Content-Type: application/json

# 请求体模板
Body: |
  {
    "alerts": [
      {{ range $index, $alert := .Alerts }}
      {{ if $index }},{{ end }}
      {
        "status": "{{ $alert.Status }}",
        "labels": {{ $alert.Labels | toJson }},
        "annotations": {{ $alert.Annotations | toJson }},
        "startsAt": "{{ $alert.StartsAt }}",
        "endsAt": "{{ $alert.EndsAt }}"
      }
      {{ end }}
    ],
    "groupLabels": {{ .GroupLabels | toJson }},
    "commonLabels": {{ .CommonLabels | toJson }},
    "commonAnnotations": {{ .CommonAnnotations | toJson }}
  }
```

## 5.4 通知策略管理

### 5.4.1 创建通知策略

通知策略定义了告警如何路由到不同的联系人。

#### 基础策略配置

1. **进入策略管理**: Alerting → Notification policies
2. **创建策略**: 点击"New specific policy"
3. **配置策略**:

```yaml
# 策略匹配条件
Matching labels:
  severity: critical
  team: infrastructure

# 联系人配置
Contact points:
  - PagerDuty Alerts
  - Slack Alerts

# 时间配置
Group wait: 30s
Group interval: 5m
Repeat interval: 1h

# 静默配置
Mute timings:
  - Weekends
  - Night hours
```

#### 多级通知策略

```yaml
# 紧急告警策略
- Matching labels: {severity: critical}
  Contact points: [PagerDuty, Slack, Email]
  Repeat interval: 10m
  Group wait: 10s

# 警告告警策略  
- Matching labels: {severity: warning}
  Contact points: [Slack, Email]
  Repeat interval: 30m
  Group wait: 1m

# 信息告警策略
- Matching labels: {severity: info}
  Contact points: [Email]
  Repeat interval: 2h
  Group wait: 5m
```

### 5.4.2 静默配置

静默允许您临时禁用特定告警，适用于维护窗口或已知问题。

#### 创建静默规则

1. **进入静默管理**: Alerting → Silences
2. **创建静默**: 点击"New silence"
3. **配置静默**:

```yaml
# 静默匹配条件
Matchers:
  - name: instance
    value: server01
    isRegex: false
  - name: severity
    value: warning
    isRegex: false

# 时间配置
Starts: 2023-01-01 02:00:00
Ends: 2023-01-01 04:00:00

# 创建者信息
Created by: maintenance-team
Comment: Planned maintenance window
```

#### 定期静默模板

```yaml
# 周末静默
- Name: Weekend Silence
  Matchers: []  # 匹配所有告警
  Schedule:
    Start: Saturday 00:00
    End: Sunday 23:59
  Comment: Weekend silence for non-critical alerts

# 夜间静默
- Name: Night Hours Silence
  Matchers:
    - name: severity
      value: warning
  Schedule:
    Start: 22:00
    End: 06:00
  Comment: Silence warning alerts during night hours
```

## 5.5 告警模板和自定义

### 5.5.1 消息模板系统

Grafana使用Go模板语法来自定义告警消息。

#### 基础模板语法

```go
// 变量引用
{{ .GroupLabels.alertname }}
{{ .CommonLabels.instance }}
{{ .Alerts }} // 告警列表

// 循环遍历
{{ range .Alerts }}
告警: {{ .Annotations.summary }}
实例: {{ .Labels.instance }}
时间: {{ .StartsAt.Format "2006-01-02 15:04:05" }}
{{ end }}

// 条件判断
{{ if eq .Status "firing" }}🚨{{ else }}✅{{ end }}

// 函数调用
{{ .Value | humanize }} // 人性化显示数字
{{ .StartsAt | time }} // 时间格式化
```

#### 高级模板示例

```go
// 多告警摘要模板
{{ define "custom_alert_template" }}
*告警状态*: {{ .Status | toUpper }}
*告警数量*: {{ len .Alerts }}

{{ range .Alerts }}
---
*摘要*: {{ .Annotations.summary }}
*严重性*: {{ .Labels.severity }}
*实例*: {{ .Labels.instance }}
*开始时间*: {{ .StartsAt.Format "15:04:05" }}
*当前值*: {{ .Value | humanize }}
{{ if .Annotations.runbook }}
*处理指南*: {{ .Annotations.runbook }}
{{ end }}
{{ end }}

{{ if gt (len .Alerts) 5 }}
*注意*: 还有 {{ sub (len .Alerts) 5 }} 个告警未显示
{{ end }}
{{ end }}
```

### 5.5.2 自定义告警标签

标签可以用于告警路由和分类。

#### 动态标签生成

```yaml
# 基于实例名称生成环境标签
Labels:
  environment: >
    {{ if regexMatch "prod-.*" $labels.instance }}
    production
    {{ else if regexMatch "staging-.*" $labels.instance }}
    staging
    {{ else }}
    development
    {{ end }}

# 基于值生成严重性标签  
severity: >
  {{ if gt $value 90 }}
  critical
  {{ else if gt $value 80 }}
  warning
  {{ else }}
  info
  {{ end }}
```

## 5.7 告警最佳实践

### 5.7.1 告警设计原则

1. **相关性**: 告警应该指向具体可操作的问题
2. **精确性**: 避免误报，确保告警准确性
3. **及时性**: 在问题影响用户前发出告警
4. **可操作性**: 告警应包含解决问题的信息

### 5.7.2 告警分级策略

```yaml
# 紧急告警 (P0)
- 服务完全不可用
- 数据丢失风险
- 安全漏洞
响应时间: < 5分钟
通知渠道: PagerDuty, 电话

# 重要告警 (P1)  
- 服务性能严重下降
- 部分功能不可用
- 容量即将耗尽
响应时间: < 15分钟
通知渠道: Slack, Email

# 一般告警 (P2)
- 性能轻微下降
- 非核心功能问题
- 信息性提醒
响应时间: < 2小时
通知渠道: Email

# 低优先级告警 (P3)
- 优化建议
- 容量规划提醒
- 维护通知
响应时间: < 24小时
通知渠道: 定期报告
```

### 5.7.3 告警疲劳避免

- **聚合相关告警**: 避免重复通知
- **设置合理阈值**: 避免过于敏感
- **使用静默功能**: 维护期间禁用告警
- **定期审查告警**: 移除不必要的告警规则

## 5.8 故障排除

### 5.8.1 常见问题解决

#### 告警不触发

- 检查查询语法是否正确
- 验证数据源连接
- 确认阈值设置合理
- 检查评估间隔和持续时间

#### 通知不发送

- 验证联系人配置
- 检查网络连接
- 确认认证信息正确
- 查看Grafana日志

#### 告警状态异常

- 检查告警管理器状态
- 验证时间同步
- 确认存储后端正常
- 查看指标数据延迟
