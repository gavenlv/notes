# 第1章：Thanos基础概念和架构

## 1.1 什么是Thanos

### 1.1.1 Thanos解决的问题

Thanos是一个开源的、高可用的Prometheus系统，旨在解决大规模Prometheus部署中的以下核心问题：

1. **数据持久化问题**
   - Prometheus本地存储容量有限
   - 数据丢失风险高
   - 长期数据存储成本高

2. **查询聚合问题**
   - 多集群数据查询复杂
   - 全局视图缺失
   - 跨集群告警困难

3. **高可用性问题**
   - Prometheus单点故障
   - 数据一致性保证困难
   - 故障恢复时间长

### 1.1.2 Thanos的核心特性

- **全局查询视图**：统一查询多个Prometheus实例的数据
- **无限数据保留**：支持对象存储长期保存数据
- **高可用性**：组件无状态设计，支持水平扩展
- **数据压缩**：自动压缩历史数据，节省存储空间
- **降采样**：支持数据降采样，提高查询性能

## 1.2 Thanos架构设计原理

### 1.2.1 整体架构图

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│    Prometheus   │    │    Prometheus   │    │    Prometheus   │
│    集群A        │    │    集群B        │    │    集群C        │
├─────────────────┤    ├─────────────────┤    ├─────────────────┤
│   Sidecar       │    │   Sidecar       │    │   Sidecar       │
└────────┬────────┘    └────────┬────────┘    └────────┬────────┘
         │                      │                      │
         └──────────────────────┼──────────────────────┘
                                │
                    ┌───────────▼───────────┐
                    │      Query组件        │
                    │   (查询路由和聚合)     │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │      Store组件        │
                    │   (历史数据查询)       │
                    └───────────┬───────────┘
                                │
                    ┌───────────▼───────────┐
                    │    对象存储           │
                    │  (S3/GCS/Azure)       │
                    └───────────────────────┘
```

### 1.2.2 数据流向分析

1. **实时数据流**
   ```
   Prometheus采集数据 → Sidecar上传 → 对象存储
   ```

2. **查询数据流**
   ```
   用户查询 → Query组件 → Sidecar(实时数据) + Store(历史数据) → 返回结果
   ```

3. **告警数据流**
   ```
   Ruler组件 → 查询数据 → 评估告警规则 → 发送告警
   ```

## 1.3 与Prometheus的关系和区别

### 1.3.1 互补关系

Thanos不是Prometheus的替代品，而是其扩展和增强：

- **Prometheus负责**：数据采集、短期存储、基础告警
- **Thanos负责**：长期存储、全局查询、高可用性

### 1.3.2 核心区别对比

| 特性 | Prometheus | Thanos |
|------|------------|---------|
| 数据存储 | 本地TSDB | 对象存储 + 本地缓存 |
| 查询范围 | 单个实例 | 全局多实例 |
| 数据保留 | 有限(通常2周) | 无限(取决于对象存储) |
| 高可用性 | 需要手动配置 | 内置高可用设计 |
| 部署复杂度 | 简单 | 相对复杂 |

## 1.4 核心组件介绍

### 1.4.1 Sidecar组件

**功能**：
- 与Prometheus实例协同运行
- 上传数据到对象存储
- 提供实时数据查询接口

**特点**：
- 轻量级，资源消耗小
- 自动发现块文件并上传
- 支持数据一致性检查

### 1.4.2 Query组件

**功能**：
- 统一查询入口
- 聚合多个数据源结果
- 查询去重和优化

**特点**：
- 无状态设计，支持水平扩展
- 支持查询缓存
- 提供PromQL兼容接口

### 1.4.3 Store组件

**功能**：
- 从对象存储查询历史数据
- 数据索引管理
- 查询性能优化

**特点**：
- 支持数据块缓存
- 自动索引构建
- 查询结果合并

### 1.4.4 Compactor组件

**功能**：
- 数据压缩和去重
- 降采样处理
- 存储优化

**特点**：
- 定期执行压缩任务
- 支持多级压缩策略
- 减少存储空间占用

### 1.4.5 Ruler组件

**功能**：
- 告警规则评估
- 全局告警管理
- 告警去重和聚合

**特点**：
- 支持Prometheus告警规则语法
- 高可用告警评估
- 灵活的告警路由

## 1.5 适用场景分析

### 1.5.1 推荐使用场景

1. **大规模监控需求**
   - 监控节点数量超过1000个
   - 需要长期数据保留(>3个月)
   - 多地域/多集群统一监控

2. **高可用性要求**
   - 业务对监控系统可用性要求高
   - 需要自动故障转移
   - 零停机升级需求

3. **成本优化需求**
   - 希望降低存储成本
   - 需要灵活的存储策略
   - 云原生环境部署

### 1.5.2 不推荐场景

1. **小规模部署**
   - 监控节点少于100个
   - 数据保留需求短(<1个月)
   - 单集群部署

2. **资源受限环境**
   - 硬件资源严重不足
   - 网络带宽受限
   - 运维能力有限

## 1.6 技术架构优势

### 1.6.1 设计优势

1. **模块化设计**
   - 组件独立部署和升级
   - 按需扩展特定组件
   - 灵活的架构组合

2. **云原生友好**
   - 容器化部署支持
   - 与Kubernetes深度集成
   - 声明式配置管理

3. **开放标准**
   - 兼容Prometheus生态
   - 支持多种对象存储
   - 标准API接口

### 1.6.2 性能优势

1. **查询性能**
   - 并行查询多个数据源
   - 智能结果合并
   - 查询缓存优化

2. **存储效率**
   - 数据压缩率高
   - 自动降采样
   - 存储分层策略

3. **扩展性**
   - 水平扩展支持
   - 组件无状态设计
   - 负载均衡友好

## 1.7 本章总结

本章介绍了Thanos的基本概念、架构设计原理以及核心组件功能。Thanos通过其独特的架构设计，有效解决了大规模Prometheus部署中的数据持久化、查询聚合和高可用性问题。

**关键要点**：
- Thanos是Prometheus的扩展，不是替代品
- 采用模块化设计，各组件职责明确
- 支持无限数据保留和全局查询视图
- 适用于大规模、高可用的监控场景
